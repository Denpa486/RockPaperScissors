# 帧数系统设计留档 · 石头剪刀升龙拳

> 本文档记录一次「帧数机制」设计讨论的全过程、决策、推演与最终结论，留作日后参考。
> 状态：**已评估 · 暂不实施**（因对体感游戏体验影响过大而取消）。

---

## 一、背景与动机

参考《街头霸王6》《恶狼传说》《拳皇》等经典格斗游戏的「帧数」机制，希望引入：

- **发生帧（Startup Frames）**：招式的起手速度，发生帧越少 → 出手越快。
- **抢断**：发生帧少的招式可以「抢断」发生帧多的招式，即快招打断慢招。

**用户原始设想**：加入更多攻击性招式，赋予不同帧数；在战斗阶段判定帧数多少，决定 Boss 还是玩家受到伤害。同时提出疑虑——作为**体感游戏**，现实中没有「帧数」概念，且更多招式会加大体感动作判定误判率、影响流畅度。

---

## 二、需求澄清与设计决策

通过多轮讨论确认了以下决策：

| 讨论项 | 确认结果 |
|--------|----------|
| 机制落点 | **方案 B：新增「快攻」招式**（识别度高，策略性最强） |
| 发生帧排序（帧越小越快） | **闪避 < 升龙 < 快攻 < 石头 = 剪刀** |
| 帧数判定时机 | **每段判定都优先帧数**（帧大者直接被抢断，帧数优先于克制表） |
| 帧数呈现方式 | **隐藏**，纯机制不提示（玩家靠试错自行摸索） |
| 手势负担 | **接受较复杂手势，但用简单动作** |
| 快攻手势 | **快速刺拳连击**（双手在胸前连续小幅度快速摆动，动态识别） |

---

## 三、逐招帧数优先推演

发生帧排序（帧越小越快）：**闪避 < 升龙 < 快攻 < 石头 = 剪刀**

若「每段判定优先帧数」，逐对推演：

| 对局 | 帧数比较 | 帧数优先结果 | 与原克制表对比 |
|------|----------|--------------|----------------|
| 升龙 vs 剪刀 | 升龙快 | 升龙胜 | ✅ 一致（升龙克剪刀） |
| 升龙 vs 石头 | 升龙快 | 升龙胜 | ✅ 一致（升龙克石头） |
| 石头 vs 剪刀 | 帧数相同 | 回落克制表 → 石头胜 | ✅ 一致 |
| 闪避 vs 升龙 | 闪避快 | 闪避胜 | ✅ 一致（闪避躲升龙） |
| 快攻 vs 石头/剪刀 | 快攻快 | 快攻胜 | ➕ 新增 |
| 快攻 vs 升龙 | 升龙快 | 升龙胜 | ➕ 新增 |
| 闪避 vs 石头/剪刀/快攻 | 闪避最快 | 闪避胜？ | ⚠️ 存疑 |

**结论**：虽然原担心帧数与克制链冲突，但推演后发现大体方向一致——升龙恰好是攻速第二快的招，石头靠「与剪刀帧数相同」回落克制表保住基本价值。该设计在方向上自洽。

---

## 四、平衡性分析与风险

推演暴露出两个真实平衡隐患，是最终取消实施的关键依据：

### 隐患 1：闪避排最快 → 可能变「万能抢断」
闪避是躲招（非攻击招），若它帧数最短且能抢断一切，将变成无敌技，破坏现有「闪避只躲升龙」的策略设计。需明确闪避的抢断边界，但当时未达成确定方案。

### 隐患 2：快攻招导致「石头」价值被严重挤压
快攻(第3快)能抢断石头和剪刀，升龙也能抢断石头，而石头(最慢)只能靠「与剪刀同速」赢剪刀。**石头会变成最弱招**——只对剪刀有效，被升龙、快攻、闪避全面克制。

### 用户核心顾虑（最终决定取消的核心理由）
1. **体感游戏不存在「帧数」概念**：帧数是对局内信息，玩家无直观感知，需 UI 翻译或靠试错，学习成本高。
2. **更多招式 → 体感误判率上升**：每加一个手势动作，相机骨骼识别误判概率增加，训练成本增加。
3. **影响操作流畅度**：更多招式 → 更长选招时间、更多判定分支、更多演出资源。

## 五、可选的替代方向（日后若重启此需求）

若未来方向改变，可按保守到激进排序参考：

- **方案 C（最保守）**：不新增招式，仅在 `BOTH_HIT`（双方对拼）时比较一个隐藏的「出招速度」属性分出先后。体感零负担，改动最小。
- **方案 A（克制链内嵌优先级）**：保持现有 4 招，给每招配一个发生帧数值，仅对拼/平手时比较先后，UI 用快/中/慢标签提示。
- **方案 B（本次讨论的方案，已评估）**：新增快攻招式 + 每段帧数优先，策略性最强，但平衡性风险与体感负担最大。

---

## 六、最终结论

**暂不实施帧数系统。** 帧数优先机制对体感格斗的体验影响过大，与「现实无帧数」的体感直觉相悖，且存在闪避万能、石头招被挤压等平衡隐患。游戏保持现有 4 招克制表与回合制连招内核不变。
